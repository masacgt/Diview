# Trouble

- A scheduled Actions run can start after the JST date changes. On 2026-10-17 the `market-calendar` job evaluated Saturday and skipped the sync even though the run had been scheduled after Friday's close. The gate now compares the latest completed XTKS session with the R2 active session on closed days, catches up only an unpublished session, and passes its date to the collector. The scheduled catch-up path remains unverified until a delayed or closed-day run exercises it.

- The yfinance R2 workflow had duplicate declarations for `yfinance-capacity-study` and `yfinance-full-universe-study`; push run #123 failed before creating jobs. Keep one definition for each job. After removing the duplicate blocks in commit `06c6faae`, push run #124 started normally and passed all 55 collector tests.
- GitHub Actions run `39089999129` passed its build job but reported one instrumentation failure on both API 26 and API 35. Sanitized logs identify `watchlistSortOrderSurvivesLeavingAndReturningToTab` and `ComposeTimeoutException`, without identifying which wait condition timed out. Local API 35 passed all 89 tests, and the API 26 480x800 focused sort test passed; preserve these as separate results and do not infer one shared root cause from the CI summary.

- The targeted API 26 Watchlist test passes on the 480x800/density240 AVD, but the same test on physical SCG01 API 33 failed at `performScrollTo()` for Apply (test line 178). The phone's logical viewport was about 502x1113, so this is neither proof of the small-screen behavior nor a confirmed product defect. Original app/test APKs were restored by hash; six of seven app-data hashes matched. `files/profileInstalled` changed during the run; cause is unconfirmed. Do not infer the control's touch behavior from this semantics-action failure.

- The API 26 Watchlist sort sheet needed vertical scrolling on small displays. The user approved that narrow interaction change; its content Column now uses `verticalScroll`, and the targeted sort-persistence test passes at 480x800/density240 through apply, tab return, and ViewModel recreation. In Actions run #36 and its retry, the full API 26/API 35 suites timed out in `watchlistSortOrderSurvivesLeavingAndReturningToTab` at 10 seconds. Commit `32e7a9d0` raised only that test's four card-order waits to 30 seconds; the API 26 and API 35 full suites in run #38 still failed at the same test after 30 seconds (88/89 API 35 tests passed). The API 35 attempt that failed during SDK image download did not run tests; its retry did. Local API 35 targeted and full 89/89 suites pass, and standard-screen Watchlist captures match on API 26 and API 35. Keep the CI failure visible and do not enlarge the CI screen or suppress the test. After these three focused attempts, make no further speculative test/UI changes; collect new evidence about the initial-order/test-order interaction first.

- API 26's `JsonReader.skipValue()` still allocates for very long JSON strings. A 52,428,767-byte legacy DVM payload saved across multiple kinds reproduced a 216,399,880-byte allocation failure under the 512 MiB heap limit. Streaming selected fields does not make this maximum input safe. The user deferred the storage/parser redesign; see `android-release-acceptance-20261018.md` before repeating a maximum-capacity test or changing the accepted limit.
- Release tests must seed their own portfolio records: fresh installations start empty. Keep test applicationContext, encrypted preferences and portable files under the same isolated wrapper. Use current calendar-year JSON keys, 0.05 yield steps, real search input and API-gated POST_NOTIFICATIONS; never reintroduce product sample data to satisfy old tests. AGP rewrites the androidTest instrumentation name from `testInstrumentationRunner`, so the optional diagnostic runner delegates normal tests to AndroidJUnitRunner and calls its initialization before diagnostic work.
- For a bounded ENOSPC check on a disposable AVD, a tmpfs in app cache requires the tmpfs `fscontext` separately from the app-data `context`; otherwise SELinux can reject the mount association. Keep the mount tiny and unmount it in finally. For backup quota checks, launch the synthetic app once after clearing it: a never-launched/stopped package returns `Backup is not allowed`. Inspect the per-package result (`Size quota exceeded`), because the overall backup command can still say Success.
- The first release CI run failed before Gradle with `sdkmanager: command not found` on the hosted runner. Provision pinned Android command line tools after selecting JDK 17, then install the existing compile SDK/build-tools versions; do not rely on the runner's PATH or change application dependency versions.

- Physical-device Compose tests can report `No compose hierarchies` while non-UI cases pass if the device is dozing. On SCG01, `dumpsys power` showed `mWakefulness=Dozing`; with JDK 17 selected, `adb -s RFCNC0E4H8J shell input keyevent 224` woke the device and the same APK passed all four audit regression tests. Preserve the first failure log and distinguish this setup failure from a product regression.
- The command-line tools at `C:\Android\sdk\cmdline-tools\bin` inferred `C:\Android` as the SDK root when creating audit AVDs and wrote `image.sysdir.1=sdk\system-images\...`. Pass `--sdk_root=C:\Android\sdk` to sdkmanager and use an absolute system-image path in the new AVD's config. The isolated API 26 and API 35 AVDs booted after this correction with JDK 17 selected.

- The legacy `/api/v1/monthly-price-history` path divided yfinance `Close` values by later split ratios even though Yahoo Finance had already split-adjusted those closes. A production Worker hotfix returns the stored close unchanged; read-back matched saved closes on split and reverse-split samples. The v2 route also returns `Close` without another adjustment. A separate production R2 repair is needed because older v2 December records stored the first day of the month as `date`; the close itself remains unchanged.
- On 2026-10-15, production `/api/v1/securities/8783` returned a legacy IRBANK fiscal-year `annual_dps_adjusted` and an older price, producing a yield from obsolete inputs. The v2 Worker and Android now read only current yfinance DPS/catalog data, prefer the later `quote_date`, and distinguish `dividend_status: unknown` from confirmed `no_dividend`. On 2026-10-17, the emulator displayed 1326 as `未取得` DPS with `0.00%` yield, while 8783 displayed DPS ¥0 and `0.00%（無配）`.
- A previous 15+15 split audit added issuer-side numeric overrides to five IRBANK rows. Those values were not yfinance event values, and calendar-year event sums cannot be equated directly with company fiscal-year DPS. The local canonical JSON and D1 input were restored; the v2 chart path uses dated yfinance events only. Under the accepted data policy, repaired yfinance event amounts are treated as split-adjusted and no later split ratio is applied again. Issuer materials for 2060, 4673, and 7161 report dividends by fiscal-year boundaries and document their consolidation dates or ratios, so fiscal totals do not independently validate a calendar-year event sum. Full-market Yahoo event-amount accuracy remains unverified; see `todo.md`.
- Root cause for the historical comparison mismatch: `annual_dps_adjusted` is a rebased fiscal-year aggregate, not a sequence of dated cash distributions. Calendar-year event sums use different date boundaries, so the two series need not match. The accepted durable path stores yfinance's repaired daily event amounts, sums by event date for calendar-year and trailing-12-month views, does not independently reapply split ratios, and identifies the graph as calendar-year history rather than issuer fiscal-year DPS.
- The v2 collector previously read `ticker.dividends`/`ticker.splits` with `repair=False`, then merged all prior dates. That could retain old duplicate or wrong amounts after Yahoo corrected an event. yfinance 1.7.0's `repair=True` path uses SciPy and scikit-learn; both dependencies are pinned, repaired coverage replaces old events, failures preserve the prior values, and the event amount basis and library versions are recorded. The first v2 R2 generation is live and the Worker financial endpoint returns yfinance calendar-year records. The remaining work is broad validation that Yahoo event amounts follow the accepted split-adjusted assumption for all securities; see `todo.md`.
- The Worker `/api/v1/dividend-months` route originally accepted `.T` symbols but passed the suffix into the four-character R2 key resolver, causing existing v2 event history to appear `not_fetched`. Normalize the optional `.T` suffix before building the R2 key. Production read-back now returns 7203's dividend months and 1326's confirmed empty history.
- Android search-catalog rows can contain `annual_dividend_per_share: 0` while `dividend_status` is `unknown`. Treating that number as DPS falsely reported ¥0. The Android repository now discards that placeholder unless the status explicitly confirms no dividend; unit tests cover unknown and confirmed-zero cases.
- `/api/v1/share-split-history` could return `empty` despite stored rows and repeated the same event when several partitions contained it. The Worker now deduplicates by event date and ratio and reports `available` when an event exists, regardless of stale empty metadata.
- Wrangler can fail with `Invalid access token [code: 9109]` when a stale `CLOUDFLARE_API_TOKEN` environment variable overrides an existing Wrangler OAuth session. Remove that variable only from the current PowerShell process before invoking Wrangler; `wrangler whoami` then confirms whether the saved browser OAuth session works. Do not print or paste token values.
- Financial migration initially keyed records only by calendar year, so fiscal periods such as 2019-03-31 and 2019-12-31 collided in `{year}.json` and 71 securities failed with `v2 period conflict`. Key newly created records by full `period_end` (`financials/YYYY-MM-DD.json`) and match existing records by exact period. Actions #74 migrated 2,982 fields for all 71 affected securities without failures; production API read-back for 1605 includes both valuation periods 2019-03-31 and 2019-12-31.
- The first weekend capacity benchmark used `datetime.now(JST).date()` instead of the latest completed XTKS session, so it targeted Saturday 2026-10-17 and failed for all sampled quotes while the workflow passed because it only checked HTTP 429. The next run used the correct expected Friday session but Yahoo had not yet returned the 2026-10-16 close. A 7203.T probe now bounds the benchmark date to Yahoo's latest available close and reports expected/actual dates. Profile failures, quote availability, and overall core success are reported separately; the job stops on HTTP 429, profile failures above 10%, or quote availability below 50%. Production sync still requires the exact expected XTKS session.
- The live-quote catalog labeled trailing-12-month cash distributions as `annual_dividend_per_share`; Android treated that field as current annual DPS and persisted it on holdings, inflating current-year portfolio totals. For example, the 2026-10-16 API response returned 630 for AOKI while its official 2027/03 forecast is 90. Keep the selected fiscal-year DPS and trailing-12-month distribution in separate fields, rebuild legacy catalog rows with an explicit unknown state when current data is unavailable, and migrate existing device caches through held-code quotes. Worker catalog/search routes suppress legacy TTM-derived annual DPS and yield until regeneration; the portfolio quote route reads current per-security documents and returns issuer-corrected values.
- A future date can be both a recurring-history estimate and the same date returned by `Ticker.calendar`. The rights-date artifact correctly marks the record `history_estimated`, but the Worker originally classified provenance by comparing date strings and consequently changed the response flag to false on an exact match. Determine the selected source first, then set `estimated_from_history` from that source; a same-date fixture now covers the case, and Worker version `85b22aae-50bc-47c0-9d40-d769be051d6a` returns the history-estimate flag correctly.
- An Android debug APK built while a second Gradle invocation was using the same output directory installed successfully but crashed at launch with `NoClassDefFoundError` for `DividendViewModel`. Wait for all Gradle processes to exit, then run one JDK 17 `:app:clean :app:testDebugUnitTest :app:assembleDebug` build before reinstalling. The clean serialized build packaged the missing class and the emulator launched successfully.
- API 26 Keystore AES-GCM bulk input can lose intermediate output in Android 8.0's chunked streamer. An 8 MiB+1 synthetic DVM payload failed authentication on immediate read-back with the old single `doFinal(input)` path, while API 35 passed. Feed at most 64 KiB per `update`, retain every output, and call `doFinal` for authentication; keep the existing IV/ciphertext/tag format. API 26/33/35 regressions now verify ciphertext length, byte equality, and tamper rejection. Already-truncated old ciphertext cannot be repaired without an intact source backup.
- `AtomicFile.openRead()` may restore `.bak` on API 26. Do not call snapshot fallback reads from a callback after `startWrite()`; first recover transferred payloads into encrypted preferences, then write from those preferences. Keep a shared lock for in-process snapshot access and use `finishWrite`/`failWrite` to close the stream. Interrupted replacement and immediate post-transfer saving are covered by the backup regression tests.
