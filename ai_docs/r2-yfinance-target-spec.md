# R2市場データ構造とアプリ取得仕様

更新日: 2026-10-17

状態: 合意済み仕様。yfinance v2の初回R2公開は2026-10-16に実施済み。実装と本番APIの確認範囲は「実装状況」を参照。

## 目的と範囲

R2の市場データをyfinance中心の構造へ移行する。J-Quants APIは銘柄コード一覧の取得に使い、銘柄データの取得元にはしない。J-Quantsデータをアプリで使う許諾は取得済みとの申告を前提とする。

本書は、採用するR2オブジェクト構造、更新処理、アプリからの取得規則を定める。財務分析入力もyfinance由来のR2データへ移行する方針とする。具体的なD1移行手順とAPI実装は含めない。移行前のデータ経路は、実装前に調査した基準情報として区別して記載する。

## 合意済みの要件

- J-Quants APIの銘柄一覧を対象ユニバースの基準とし、株式、ETF、REITを含める。
- 日本市場の営業日の市場終了後に更新する。休場日は日本市場カレンダーで判定して取得を行わない。
- 会社情報、現在配当、価格、財務入力値は、現在のアプリ表示または計算に必要な項目だけを保存する。
- 銘柄情報はyfinanceから取得し、`ja-JP` / `JP` ロケールを指定する。名称は `shortName`、`longName`、英語名の順に使う。
- 配当・分割履歴は通常領域に直近10年を保存し、10年を超える履歴は期間を定めずアーカイブする。
- 最新価格に加え、銘柄情報画面の配当実績で使う直近8確定年の12月終値だけを保存する。直近13か月内の年末価格は通常領域、それより古い対象価格はR2アーカイブに置き、8年の対象期間を外れた価格と12月以外の月次価格は削除する。
- 既存のyfinance領域にある不要項目もアーカイブし、10年間保持する。IRBANK領域全体は不要データの一括アーカイブ対象に含めない。ただし、移行中にアプリ必須値の代替として使った旧値は、移行後に個別にアーカイブする。
- J-Quants一覧から外れた銘柄は定期取得と新規検索・登録の対象から外す。保存済みの履歴は保持し、既存保有銘柄では保存済みデータを表示する。
- yfinanceの取得失敗時は前回データを保持し、失敗状態を記録する。
- 正常応答で配当履歴が空の場合は空履歴として記録し、毎営業日に再確認する。
- 移行中にyfinanceから取得できないアプリ必須項目は旧データを維持し、取得状況を記録する。項目ごとにyfinance値または未取得状態を確認してから切り替え、旧値は切替後にアーカイブへ移す。切替後にyfinanceで取得できない項目は未取得として記録し、その項目を必要とする表示・計算だけを省く。銘柄情報画面のDPS欄は未取得と表示し、配当利回りだけは未取得時も `0.00%` とする。取得状態は未取得のまま保持し、無配当が確認された状態とは区別する。
- アプリは端末ごとに日本時間の日付単位でR2の一覧データを取得する。正常取得は日本時間の同じ日に1回までとし、最後に成功した取得から12時間未満の場合は日付が変わっていても一覧を再取得しない。失敗試行は成功時刻を更新せず、次回アプリ起動時に再試行できる。
- 銘柄を新規登録するときや検索結果を表示するときは、その銘柄の情報をその都度取得する。
- 検索・登録対象はR2に存在する銘柄データに限る。R2にない銘柄は検索結果に出さず、その場でyfinanceへ問い合わせない。
- ライブ価格更新は行わない。価格は市場終了後に取得した日次値を使う。
- 取得失敗後はランナーを待機させず、失敗銘柄・項目を次回以降のジョブで優先して再試行する。同一銘柄の再試行は1営業日あたり最大3回（初回を含め合計最大4回）とし、翌営業日に回数をリセットする。

## 移行前の実装で確認したデータ経路

以下はv2実装前のコード調査結果であり、現行リポジトリのWorker実装や移行後の仕様を示すものではない。本節の旧キー・旧API経路は移行対象を説明するために残す。

### 銘柄検索と登録

Androidの `searchSecurities()` はWorkerの `/api/v1/security-search` を呼ぶ。現在WorkerはR2の `market/irbank/v1/catalog.json` から銘柄コードと名称を検索し、検索結果に対応する価格、年間配当、利回りを `market/yfinance/search_catalog.json` から補う。銘柄登録時の `getSecurity()` は `/api/v1/securities/{code}` を呼び、IRBANK概要から名称、直近配当、最新財務値を読む。

移行後は銘柄一覧をJ-Quants由来コードで構成し、名称は日本語ロケールのyfinance値を使う。検索カタログには検索と一覧表示で実際に使うコード、表示名、最新価格、直近12か月の配当イベント合計、配当利回りを含める。J-Quants銘柄コードに市場サフィックスを付けてyfinanceシンボル候補を作り、初回に銘柄基本情報と最新価格をR2へ保存できた後で検索カタログへ登録する。ほかの個別項目がyfinanceで取得できない場合は未取得状態で記録し、その項目に依存する表示・計算だけを省く。初回取得に失敗した銘柄はユニバースの取得状態を保って再試行するが、検索対象には含めない。検索・登録はR2に公開済みかつJ-Quantsの有効ユニバースに含まれる銘柄データだけを対象とし、R2に未登録の銘柄を検索時にyfinanceから取得しない。新規ユニバース銘柄は定期更新ジョブでR2に登録されてから検索可能になる。ユニバースから外れた銘柄は新規検索・登録できないが、既存保有銘柄では保存済みデータを表示する。業種表示は現在のAndroid同梱業種マスターを継続利用し、銘柄検索用R2データには含めない。

### 移行前の価格一覧と検索カタログ

Androidは `/api/v1/search-catalog` から価格カタログを読み、`/api/v1/live-quotes` をページングして更新完了済みの価格を反映する。カタログでは銘柄コード、価格、価格日、年間配当、利回りを使う。

現在の `live-quotes` はCloudflare WorkerがYahoo Finance Chart APIを直接呼び出して生成している。Pythonのyfinance処理とは別経路であり、yfinanceへ統一する際にこのWorker側ライブ取得を終了し、yfinance更新ジョブが生成した最新日次価格と完了状態を配信する必要がある。

検索結果の人気順API `/api/v1/popular-holdings` はWorkerに存在するが、Androidソースに呼び出し箇所は見つからなかった。現行アプリの必須データとは判定しない。

### 配当実績に使う年末価格

Androidの銘柄情報画面は、配当実績の初期値として直近8確定年それぞれの12月終値を要求する。現行Androidソースで `AssetTrackingSection` は定義されているが呼び出しがなく、年間資産推移の月次価格要求は画面から到達できない。そのためR2には、銘柄ごとに最大8件の12月価格を保存し、10年分の全月次価格は保存しない。

既存の `/api/v1/monthly-price-history` 応答形式と `prices/monthly/{year}.json` の年別パーティションは維持し、各パーティションには12月の1点だけを格納する。価格はyfinanceの `Close`（株式分割調整済み、配当再投資調整なし）とし、価格日はXTKSカレンダーから12月の最終営業日を記録する。直近13か月に含まれる価格は通常領域、残りの7年分は `archive/prices/monthly/{symbol}/{year}.json` に保存する。Workerは要求された12月だけ通常領域とアーカイブから返す。

### 移行前の配当月・権利日

Androidの `/api/v1/dividend-months` 呼び出しは、配当日、1株当たり金額、直近365日の配当月、今後の権利関連日を使う。Workerはv2配当イベントと `current.json` のex-dividend dateを読み、`derived/rights_dates/current.json` の計算済み権利日を結合する。計算値はXTKS営業日カレンダーに基づく推定として扱い、会社が公表した権利確定日とは区別する。

新構造では配当イベントを正本として10年分保存する。権利付き最終日や推定権利確定日は配当イベントそのものと区別し、XTKSカレンダーから得た計算値として管理する。Yahooのex-dividend dateを会社確定のrecord dateとして扱わない。

### 移行前の財務情報と株式分析

Androidの `/api/v1/financial-data/{code}` は現在IRBANK概要から年次財務、決算期別配当、評価指標を読む。アプリは次の値を表示または計算に使う。

- 年次配当: `fiscal_year`、`annual_dps_adjusted`、配当性向、連続増配年数、DOE
- 年次財務: 売上高、営業利益、営業CF、投資CF、自己資本比率
- 評価指標: 調整後EPS、調整後BPS、調整後配当利回り
- 派生値: 営業利益率、FCF比率、連続非減配年数、5年DPS成長率、配当利回りの最小・平均・最大

現行Androidの `FinancialData.kt` が実際に使う年次財務入力は、売上高・営業利益から算出する営業利益率、営業CFと投資CFの合計から算出するFCF比率、自己資本と総資産から算出する自己資本比率である。年次評価値はEPS、BPS、配当利回りを使う。純利益、損益計算書のEPS、発行株式数、設備投資額はこの画面の計算に使わないため、yfinanceから取り出してR2へ保存しない。

移行前は、IRBANKの調整済み決算期別DPSを第一候補にし、統合銘柄データ中のyfinance配当イベントを暦年で合計した値を代替にしていた。移行後はyfinanceの返却配当額を分割調整済みとして扱い、追加の比率換算はしない。暦年のイベント合計と会社公表の決算期DPSは期間定義が異なるため、数値の一致は保証しない。

Workerの `/api/v1/analysis/{code}` は現在D1の銘柄指標・年次財務・配当データとR2の現在価格・PER・PBRを組み合わせ、PER、PBR、配当性向、自己資本比率、営業利益率、FCF比率、連続増配年数を計算する。移行後は、これら分析に必要な入力値もyfinance由来のR2データへ移し、分析APIのD1依存を解消する方針とする。yfinanceで取得できない入力値は未取得として記録し、その値が必要な指標だけを返さない。D1からR2への項目単位の切り替えでは、yfinance値または未取得状態を確認してから切り替え、旧値をアーカイブする。

## 採用するR2オブジェクト構造

```text
market/yfinance/v2/
  manifest.json
  universe/current.json
  catalog/current.json
  catalog/generations/{session-date}.json
  publications/current.json
  derived/rights_dates/current.json
  securities/{symbol}/
    profile.json
    current.json
    prices/monthly/{year}.json
    dividends/{year}.json
    splits/{year}.json
    financials/{fiscal-year}.json
    sync.json
  archive/
    events/{symbol}/dividends/{year}.json
    events/{symbol}/splits/{year}.json
    prices/monthly/{symbol}/{year}.json
    legacy/securities/{symbol}/unused.json.gz
```

`universe/current.json` はJ-Quantsから取得したコード、市場サフィックス付きyfinanceシンボル候補、銘柄種別、上場状態、初回取得状態を保持する。初回の銘柄基本情報と最新価格を保存できた銘柄だけを検索カタログへ登録する。シンボル候補を解決できない場合はunsupported、初回取得が失敗した場合はfailedとして記録し、検索対象外のまま再試行する。銘柄がJ-Quants一覧から外れた場合はinactive状態にし、新しい取得対象から外す。既存v2銘柄データは削除しない。旧yfinance銘柄JSONは、必要項目のv2移行と不要項目のアーカイブ読戻しを確認した後に限って削除する。

`profile.json` はコード、yfinanceシンボル、`shortName`、`longName`、表示名など、銘柄名表示に必要な情報だけを持つ。取引所、国、事業概要、時価総額、プロフィール上の発行株式数は保存しない。市場・商品区分はJ-Quantsの銘柄一覧を使い、業種情報は現在のAndroid同梱業種マスターを使う。通貨は現在価格の単位として `current.json` にのみ保存する。

`current.json` は最新の市場終了価格と価格日、直近12か月の配当イベント合計による実績年間配当額、次期配当見込み、今期配当実績、配当利回り、PER、PBRなど現在表示・計算に使う値を持つ。利回りは次期配当見込みを最新終値で割って算出し、見込みがない場合は今期配当実績を使う。実装ではyfinanceの `dividendRate` を次の12か月の配当見込みとして記録する。この値は会社が確定した次会計年度DPSとは区別する。代替の今期配当実績は、yfinance配当イベントのうち現在の会計年度に属し、取得日までに記録された金額の合計である。両方取得できない場合、データ状態は未取得として保持し、アプリでは `0.00%` と表示する。金額の取得基準は `event_amount_basis: yfinance_split_adjusted_assumption` に記録し、yfinanceの返却額を分割調整済みとして扱う。

銘柄情報画面の現在DPSと利回りは `current.json` の次期見込み、または取得できない場合の今期実績から求める。利回りはそのDPSを最新終値で割って計算し、DPSが未取得なら `0.00%` とする。過去の暦年イベント合計、利回りだけの値、旧APIの `annual_dps_adjusted`（決算期集計）は現在DPSへ代用しない。株価は詳細データと検索カタログの価格日を比較し、より新しい日付の終値を使う。

`prices/monthly/{year}.json` は直近8確定年の12月価格を年ごとに最大1点格納する。初回取得では対象8年の yfinance 月間足を取得して12月分だけ残し、以後は12月の最終XTKS営業日後に当年12月価格を更新する。12月以外の月次価格、8年の対象期間より古い価格は保存しない。直近13か月に入る最新の12月価格は `securities/{symbol}/prices/monthly/{year}.json`、それ以前の対象年は `archive/prices/monthly/{symbol}/{year}.json` に置く。価格日はXTKSの12月最終営業日とし、`Close` は株式分割調整済み・配当再投資調整なしである。既存R2月次履歴は銘柄の初回v2年末価格同期時に12月価格だけへ整理し、通常領域から不要月を削除する。

`dividends/{year}.json` と `splits/{year}.json` はイベント日をキーに保存する。日次同期では固定したyfinance 1.7.0、SciPy 1.18.1、scikit-learn 1.9.1を使い、価格取得と同じ `history(period="1y", interval="1d", actions=True)` のイベント列を変更検知候補として使う。この日次応答は `repair=False` であり、未修復の候補値を保存済みイベントへ反映しない。候補に変更があれば、該当期間を `history(actions=True, repair=True)` で取り直し、成功した範囲を修復済みの応答で置き換える。全期間の修復済み履歴は銘柄コードのハッシュで20群に分けて順番に再取得し、新しい分割・併合を検出した銘柄は同日に全期間を再取得する。SciPyは単位混同検出、scikit-learnは破損価格区間の再構成でyfinanceから利用される。イベント金額は修復処理後にyfinanceが返した値を分割調整済みとして扱い、アプリ側・Worker側で株式分割比率を再適用しない。取得失敗時は前回イベントを保持し、失敗状態を記録して次回以降のジョブで再試行する。通常領域から10年を超えたイベントを `archive/events/` へ移し、アーカイブは無期限で保持する。取得条件、ライブラリバージョン、対象期間、イベント金額基準は銘柄の `current.json` と各イベントオブジェクトに記録する。

配当履歴グラフは修復済みyfinance配当イベントをイベント日が属する暦年ごとに合計する。yfinanceが返す配当額と株価は分割調整済みとして扱い、独自の分割比率換算は加えない。IRBANKの `annual_dps_adjusted` や会社公表の決算期DPSを配当イベント値として混在させない。画面のタイトルは「1株配当金の実績（最大8期）」とし、yfinance由来であることを示す追加ラベルは表示しない。8期分の株価と年間配当金は銘柄情報画面の編集アイコンから編集できる。株価の初期値は各年12月の最終営業日終値、年間配当金の初期値はR2のyfinanceイベント暦年合計とする。編集画面は他の検索シートと同様に下から表示するボトムシートとし、8期を8行で並べ、縦スクロールなしで株価・年間配当金を入力できる。`/api/v1/share-split-history` から同じ8年間の分割・併合日と比率を読み、イベントが属する年の行に併記する。比率が1より大きいイベントを株式分割、1未満を株式併合として表示し、未取得・取得失敗・イベントなしを区別する。株価と配当金額は項目ごとに「初期値」または「ユーザー編集」と表示する。編集差分は暗号化して端末内に保存し、R2の共有値は変更しない。「初期値に戻す」は編集中の値を初期値に戻し、「保存」を押すと端末内の編集差分を削除して最新の取得値を表示する。

`financials/{fiscal-year}.json` はアプリが使う年次財務入力値だけを格納する。各項目についてyfinance値または未取得状態を確認してから切り替える。更新対象は5つの順番付きグループに分け、各営業日に1グループを取得する。取得に失敗した銘柄・項目は次回ジョブで優先して再試行する。yfinanceの取得に失敗した項目は切り替え完了まで旧データを維持し、出所と取得状態を記録する。切り替え後に旧値をアーカイブする。

`sync.json` は銘柄単位の最終試行日時、最終成功日時、当日の試行回数、状態、失敗理由を持つ。銘柄全体の状態は `running`、`ok`、`partial`、`failed` を区別し、個別項目は `available`、`empty`、`stale`、`failed` を区別する。上場廃止銘柄はユニバース側で `inactive` とし、空応答と通信・解析エラーを同じ状態にしない。

`catalog/current.json` はアプリの検索と価格一覧に必要な軽量フィールドだけを集約する。`publications/current.json` は公開世代、対象銘柄一覧の更新日、更新完了日時、成功・失敗件数を示す。銘柄単位で取得に失敗しても、成功分の新データと失敗分の前回データを組み合わせた世代を公開する。カタログ生成そのものに失敗した場合は現行公開世代を維持する。

`archive/legacy/securities/{symbol}/unused.json.gz` は旧yfinance銘柄JSONからv2へ移さない価格履歴・財務項目などだけを元キーと対応づけて10年間保存する。gzipアーカイブの読戻しを確認した後に旧銘柄JSONを削除する。配当・分割イベントと月次価格の履歴アーカイブとは保持期限を分ける。

## 更新ジョブ

1. 日本時間21時17分にジョブを起動し、XTKS営業日カレンダーで当日が取引日か確認する。休場日はJ-Quants・yfinanceの取得を行わない。
2. J-Quantsから銘柄一覧を取得し、前回一覧との差分から新規、継続、上場廃止を判定する。
3. 有効銘柄すべてについて、yfinanceから日本語名、当日XTKS営業日の日付と一致する日足 `Close`、現在統計を取得する。価格取得と同じ直近1年の日足応答から配当・分割の変更候補を読み、変更がある場合だけ `history(actions=True, repair=True)` で該当期間を取り直す。候補の未修復値で既存の修復済みイベントを上書きしない。当日終値が取得できない場合は銘柄の更新を失敗として記録し、前回の価格を保持する。前日終値を当日価格として公開しない。
4. 全期間の配当・分割履歴と初回8年分の12月価格は20群のうち当日分を取得する。直近1年に新しい分割・併合を検出した場合は、その銘柄の全期間イベントと8年分の12月終値をyfinanceから再取得し、R2上の既存値を更新する。年次財務・評価値は初回のみ5群に分けて取得し、その後はyfinanceの `lastFiscalYearEnd` または `mostRecentQuarter` の更新時、あるいは前回確認から45日経過した場合に取得する。失敗した財務系統はその系統だけ再試行する。12月価格は12月の最終XTKS営業日後に全銘柄を更新する。実行時間とyfinance呼び出し数を公開状態とActionsログへ記録し、月間2,000分の上限に対して実測値を確認する。
5. 取得に失敗した場合は前回成功データを保持し、失敗銘柄・項目をR2の同期状態に記録して後続ジョブで優先する。部分成功後の同一営業日内の再実行では、成功済みの企業情報、終値、イベント、財務系統を再取得せず、失敗項目だけを再試行する。失敗で前回成功データがない場合は、銘柄の初回取得に必要な項目を取得する。ランナーを待機させる再試行は行わず、同一銘柄の試行は営業日あたり最大4回とする。正常な空配当履歴は `empty` として記録し、次の営業日にも確認する。
6. 直近8確定年の12月価格だけを保持し、通常領域・価格アーカイブを同期する。10年境界を超えたイベントと不要な旧yfinanceオブジェクトも所定のアーカイブへ移し、書き込み・読戻しの確認後に通常領域から取り除く。
7. 全銘柄の処理後に検索カタログと公開世代を更新する。取得成功銘柄は新データ、失敗銘柄は前回成功データを含めたカタログを公開し、完了日時と未取得・失敗件数を記録する。

アーカイブ移動中は、移動先の書き込みと読戻しを確認してから通常領域の削除を行う。移行処理は再実行可能にし、同じイベントや月次価格を重複登録しない。

## アプリからの取得

R2バケットは非公開のままにし、AndroidアプリはWorker APIを通じて読む。

### 一覧取得

- アプリは端末ごとに日本時間の日付を基準に、検索・価格一覧の軽量カタログを取得する。
- 最後に成功した取得から12時間未満なら一覧全体を再取得しない。さらに、日本時間の同じ日に成功済みなら一覧全体を再取得しない。
- 12時間の抑止とJST日次の成功取得上限を端末ごとに管理する。保存する値は端末内の最終試行時刻、最終成功時刻、最終成功JST日付とする。別端末での取得状況とは共有しない。
- 取得に失敗した場合、端末の前回成功キャッシュを保持し、最終成功時刻を維持する。失敗試行は成功取得回数に含めず、次回アプリ起動時に再試行できる。

### 銘柄検索・登録・詳細表示

- 検索実行時は検索APIを呼び、R2に公開済みのカタログ内でコード・名称を検索する。検索候補の価格・価格日・配当利回りも同じR2カタログの値を使う。R2にない銘柄は検索されず、検索を契機とするyfinance取得も行わない。
- 候補を選択したときは、その銘柄のプロフィールと現在値を個別にR2から取得する。検索一覧のために銘柄別履歴や全詳細データを一括取得しない。
- 新規登録時は選択銘柄のプロフィールと現在値だけを取得する。全銘柄の詳細JSONや配当履歴を端末へ一括取得しない。
- 詳細画面や配当表示を開いたときに必要な配当イベント、年次財務、評価値を銘柄単位で取得する。
- 配当実績用の12月価格は要求された月だけ取得し、端末に銘柄・年月単位でキャッシュする。過去の対象年はWorkerがR2アーカイブから参照する。
- 銘柄詳細がR2に存在しない場合は検索・登録対象にならない。ユニバースに含まれるが取得失敗した銘柄はカタログ上で取得状態を記録し、前回データを保持したうえで指数バックオフにより再試行する。

## API移行方針

既存Androidクライアントとの互換性を保つため、APIの応答形式を維持し、Worker内部のR2キー参照を新構造へ切り替える。検索、銘柄詳細、日次価格、配当イベント、月次価格はv2だけを参照する。財務APIの旧値参照は、項目ごとの移行確認が済むまで互換層として残し、確認後に削除する。

検索カタログと銘柄検索はv2カタログだけを参照する。v2カタログ公開前は検索APIを利用不可として返し、旧IRBANKカタログや旧yfinanceカタログへフォールバックしない。銘柄登録APIもv2カタログに掲載され、プロフィールと現在値を保存済みの銘柄だけを返す。これにより初回yfinance取得に成功する前の銘柄は検索・登録できない。既存保有銘柄の表示には端末に保存した値を使う。

| アプリAPI | v2実装が読むデータ |
|---|---|
| `/api/v1/search-catalog` | `catalog/current.json` |
| `/api/v1/security-search` | `catalog/current.json` のコード・表示名・価格・価格日・配当利回り |
| `/api/v1/live-quotes` | yfinance更新ジョブが公開した日次価格のページ。WorkerからYahooへライブ取得しない |
| `/api/v1/monthly-price-history` | `prices/monthly/` と直近8確定年の12月価格アーカイブ |
| `/api/v1/dividend-months` | 直近365日の配当イベントと権利日派生データ |
| `/api/v1/securities/{code}` | `profile.json` と `current.json` |
| `/api/v1/financial-data/{code}` | `financials/`、配当履歴、評価入力値。未取得項目は状態付きで返す |
| `/api/v1/analysis/{code}` | 銘柄の財務・配当・価格入力はv2を優先し、分析定義と分析履歴は現行D1/KVを使う |
