# WatchList インカム空白月解消アドバイス仕様

## 目的

WatchList の受取月別試算で、試算上の空白月を補える可能性がある監視候補を提示する。候補は購入推奨ではなく、V2 に保存された配当・財務情報を使った比較材料とする。

この文書は合意した仕様と実装状態を記録する。

## 月別試算と空白月

- 空白月は、現在の WatchList 月別試算で当該月の試算額が 0 円となる月とする。
- 試算対象は各銘柄の取得済み配当イベント月とし、年間配当額を対象月に均等配分する。日本株は 100 株、米国株は 1 株を試算単位とし、税引前で計算する。
- 配当月未取得の銘柄は「配当なし」と見なさず、試算対象月へ割り当てない。未取得銘柄数を別に示す。
- 配当イベントの日付は実際の入金日を示さない。画面上は「試算上、配当見込みがない月」と表現し、「実際の受取月ではない」ことを説明する。

## V2 データ経路

### 元データ

V2 の銘柄データを元に候補一覧を生成する。

| 用途 | V2 のデータ |
| --- | --- |
| 銘柄コード、名称、価格、通貨 | `market/yfinance/v2/catalog/current.json`、`securities/{symbol}/profile.json`、`securities/{symbol}/current.json` |
| 配当イベント日と1株当たり金額 | `securities/{symbol}/dividends/{year}.json` |
| 次期配当予想、PER、PBR、配当性向 | `securities/{symbol}/current.json` |
| 年次財務、自己資本比率、営業利益率 | `securities/{symbol}/financials/{period-end}.json` の最新年次レコード |
| 暦年の連続増配年数、非減配年数と計算状態 | `securities/{symbol}/current.json` の `dividend.calendar_year_metrics` |

V2 配当イベントの合計は暦年実績であり、決算期の年間 DPS として代用しない。分割調整済みとされる yfinance のイベント額に、アプリまたは Worker で分割比率を再適用しない。

### 候補データ生成・API

1. yfinance V2 同期後、V2 のカタログ・銘柄データ・配当イベントから候補用一覧を生成する。
2. 派生一覧を `market/yfinance/v2/derived/income_advice/current.json` に保存する。レコードごとに元の V2 カタログ世代、計算日時、採点項目ごとの値・出典・状態を保持する。
3. Worker に `GET /api/v1/income-advice-candidates` を設け、候補一覧、世代、生成日時を返す。
4. Android はこの一覧をキャッシュする。更新は他の通常データと同じく、日本時間で同日なら行わず、前回取得から12時間未満でも行わない。
5. 空白月や WatchList が変わったときは、キャッシュ済み候補一覧から順位を再計算する。ユーザー操作ごとに Worker や yfinance へ個別銘柄を問い合わせない。

派生一覧は計算・検索用であり、元データは銘柄別 V2 オブジェクトを正とする。R2 に未公開の銘柄を候補表示のためにその場で yfinance から取得しない。

## 候補の適格条件

次の条件をすべて満たす銘柄を候補に含める。

- V2 の有効な国内上場銘柄である。
- WatchList に未登録である。
- 直近3つの完了暦年のうち2年以上で確認された配当イベント月が、現在の試算上の空白月と1か月以上重なる。
- 次期配当予想、またはイベント履歴が通年分取得できた直近完了暦年の配当合計が確認できる。
- 配当性向、自己資本比率、営業利益率、PER、PBR、連続増配年数、非減配年数の7項目が採点可能な状態である。
- 必要な項目の取得状態が `available` である。`empty`、`failed`、`stale`、`not_fetched` は採点可能と見なさない。

直近3完了暦年の配当イベント月は、3年中2年以上にイベントがある月だけを候補の観測月とする。1年だけのイベント月は、継続的な配当月として扱わない。

候補の年間配当額は、V2 の次期配当予想が `available` ならそれを使う。予想がない場合は、履歴が通年分確認できる直近完了暦年のイベント合計を参考額として使い、画面に「前年実績ベース」と表示する。どちらも確認できない場合は候補から除外する。未取得・失敗を0円として扱わない。

## 通貨

- 初回対象は V2 の国内銘柄カタログにある JPY 建て銘柄に限定する。円換算係数は1とする。
- JPY 以外の銘柄は、V2 に為替データ経路が用意されるまで候補から除外する。Android の別為替 API で不足を補わない。
- 将来、外貨建てを対象にするときは為替レートも V2 に保存し、通貨ペア、レート、基準日、出典を候補情報に付ける。必要なレートがない銘柄は金額試算・順位付けの対象外とする。

## 総合スコア

候補の品質比較に100点満点の参考スコアを使う。各値は V2 の最新利用可能な値を所定の単位へ正規化して採点する。境界値は表記どおり上限を含む。

| 指標 | 配点 | 得点基準 |
| --- | ---: | --- |
| 配当性向 | 20 | 30%以下=20、50%以下=16、70%以下=12、90%以下=6、100%以下=3、100%超または負値=0 |
| 自己資本比率 | 20 | 60%以上=20、40%以上=16、30%以上=12、20%以上=8、10%以上=4、10%未満または負値=0 |
| 営業利益率 | 15 | 15%以上=15、10%以上=12、5%以上=9、0%以上=5、0%未満=0 |
| PER | 10 | 0超10倍以下=10、15倍以下=8、20倍以下=6、30倍以下=3、30倍超または0以下=0 |
| PBR | 10 | 0超1倍以下=10、1.5倍以下=8、2倍以下=6、3倍以下=3、3倍超または0以下=0 |
| 連続増配年数 | 15 | 5年以上=15、4年=12、3年=9、2年=6、1年=3、0年=0 |
| 非減配年数 | 10 | 10年以上=10、7〜9年=8、4〜6年=6、2〜3年=3、1年=1、0年=0 |

7項目すべてのデータ状態が採点可能である銘柄のみ総合スコアを計算する。不足項目を0点に置き換えず、その候補は「評価データ不足」として順位対象から外す。取得済みの値が不利な範囲に該当する場合は表のとおり0点を付ける。

このスコアは候補を並べるための共通基準であり、業種別の補正は行わない。画面では「候補比較スコア」と表示し、「安全性」や「買い推奨」とは表現しない。

## 並び順

1. 総合スコアの高い順
2. 同点なら、空白月を多く補える順
3. それも同じなら、1単元あたりの年間配当額が大きい順
4. さらに同じなら、証券コードの昇順

表示件数は最大3件とする。

## 試算額

- 日本株は100株、税引前、円建てで計算する。
- 候補の年間配当額を、直近3完了暦年のうち2年以上で観測された配当イベント月に均等配分する。
- 空白月と候補の観測イベント月の積集合を「補える見込みの月」として示す。
- 試算額は過去の配当イベント月と年間配当額に基づく参考値であり、将来の配当額、権利日、実際の入金月を保証しない。

## 表示・操作

カード見出しは「インカム空白月の候補」とする。試算上の空白月、候補のコード・名称、候補比較スコア、補える見込みの月、月額試算、年間配当額の基準（次期予想または前年実績ベース）を表示する。

候補追加操作は「監視銘柄に追加」とする。これは WatchList 登録であり、購入操作ではない。登録済み銘柄は候補一覧に表示しない。

空白月がない場合は候補一覧を表示せず、「現在の試算では、すべての月に配当見込みがあります」と表示する。候補条件を満たす銘柄がない場合は「条件を満たす候補がありません」と表示する。候補一覧の取得に失敗した場合は空一覧と区別し、「候補情報を取得できません」と表示し、既存キャッシュがあれば保持する。

説明文は次の内容を伝える。

> 配当イベント月と年間配当額を使った税引前の概算です。年間配当額は観測されたイベント月に均等配分しています。実際の権利日や入金月、将来の配当額を示すものではありません。

## 実装状態

ローカルコードには、V2 同期時の候補スコア・候補用派生オブジェクト生成、Worker の `GET /api/v1/income-advice-candidates`、Android の起動時取得・日付/12時間ゲート付きキャッシュ・空白月に応じた最大3件の表示を実装した。アプリへの候補登録は既存の WatchList 登録処理を使う。

本番 Worker へのデプロイと、R2 の `derived/income_advice/current.json` 初回生成・読戻しは未実施である。したがって本番環境で候補を表示するには、その公開と生成の確認が必要。
