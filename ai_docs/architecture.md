# Architecture

## Runtime and storage

- Fetch efficiency shares R2 JSON/list reads within one Worker request and overlapping HTTP GETs across Android's default screen/notification repositories, without retaining completed HTTP responses or changing refresh policies. Explicit catalog downloads prime the existing search fallback cache; monthly batches omit wholly current months. Current Android security requests use `include_history_bounds=false` to skip unrendered archive scans while older API clients keep full metadata. See [data-fetch-efficiency-implementation-20261027.md](data-fetch-efficiency-implementation-20261027.md) for differential response, device image, and production publication evidence.

- Asset-management industry labels can be supplemented by J-Quants `ProdCat`. `GET /api/v1/security-categories` reads the complete R2 `market/yfinance/v2/universe/current.json`, including securities without price/catalog entries, and supports optional batches of up to 200 codes. Android persists successful per-code lookups for 45 days in `cloudflare_market_cache/security_categories_v1`; failed refreshes retain cached labels without renewing their timestamp. Only unclassified Japanese holdings display `013` as `REIT（不動産投資信託）` or `014` as `ETF（上場投資信託）`; persisted holdings and industry analysis keep the TSE33 industry. The existing Actions ingestion schedule is unchanged. See `ai_docs/security-product-categories.md` for validation and publication status.

- ローカルの `scripts/jquants_v3/` はJ-QuantsのみのSQLiteスナップショットを作る。日足・月次価格に加えて、J-Quants APIの銘柄マスター、評価指標、財務サマリー、営業日を保存する。2026-10-25時点のキーで取得できる日足等は2026-08-02までの遅延データ（最終取引日は7/31）。配当明細と財務明細はPremium限定で取得不可。実収録範囲と未取得項目は `scripts/jquants_v3/README.md` とDB内 `dataset_coverage` を参照。ローカルデータは `local_artifacts/` に置き、Cloudflareへは配信していない。

- New support feedback is saved with a transactional D1 email outbox (`support_feedback_email`, migration 0006). The Worker notifies the configured verified admin via Cloudflare Email Service; existing hourly cron retries up to 20 pending messages with a 10-minute lease. Delivery is at-least-once; old receipts are not backfilled and deletion removes outbox records. See `data/irbank/cloudflare/docs/feedback-email.md`.

- The current app source is `kurogane-dividend/`; Android builds come from `kurogane-dividend/android/`.
- Android Compose typography uses the platform sans-serif family for interface text and financial figures; shared numeric styles enable tabular figures (`tnum`). Monospace is reserved for identifiers and technical literals. No custom font files are bundled.
- Android portfolio CSV import supports six broker labels and keeps CSV export unencrypted at a user-selected device destination. Encrypted Drive backup uses the reference APK's AES-256-GCM DVM format for holdings plus a Diview DVM sidecar for shareholder-benefit, stock-climate, and dividend-history overrides; OAuth/Drive setup is external. See `ai_docs/portfolio-import-backup-spec.md` for file formats, restore behavior, and limits.
- Newly held securities trigger background acquisition of market/security data, IRBANK quote values, Japanese annual financials and analysis, dividend-month data, and the seven year-end price points used by Stock Detail's initial history chart. This applies to portfolio updates and registrations, including CSV/DVM imports. Quote values, security snapshots, financial documents, analysis values, dividend schedules, and monthly prices are stored in app-private `cloudflare_market_cache` preferences; updated holdings are saved through the encrypted local holdings store. Stock Detail requests missing security data for tracked codes instead of treating portfolio membership as proof that a cache exists. It preloads up to eight calendar years of dividend events on initial load through one `event_years` request and displays cached events on year selection; the client falls back to legacy single-year requests when an older Worker does not acknowledge the requested range. Split history remains fetched on demand and cached.
- The Cloudflare Worker API is in `data/irbank/cloudflare/src/index.js` and uses D1 for operational records and R2 bucket `diview-market-data` for market snapshots.
- The Worker binds R2 as `MARKET_DATA`. R2 public URLs remain disabled; selected objects are served by explicit Worker routes.
- IRBANK financial seed values retain per-record `field_units` from source metadata; the shared contract supplies fallback units only when metadata is absent. The financial-data API converts declared `million_jpy` and `hundred_million_jpy` values to JPY in app-facing rows and preserves original seed values and units. Unknown units are not guessed, and equity-ratio output requires matching input sources and compatible explicit units or a valid IRBANK-reported percentage.
- Current IRBANK issuer DPS and company forecasts are published in `market/yfinance/v2/issuer_dividends/current.json`. Per-security Worker routes read a code-prefix shard selected by `issuer_dividends/shards/current.json` instead of parsing the full index on every request. Shards are written to the inactive A/B slot and read-back verified before the manifest switches; the full index remains for catalog-wide routes. `refresh_v2_dividends.py`, `refresh_v2_dividend_batch.py`, and `refresh_v2_dividend_yields.py` maintain the shard set; `sync_v2_dividend_index_shards.py` initializes it from the current full index. The scheduled `irbank-v2-dividend-batch.yml` job runs daily and caps authenticated IRBANK requests, including retries and the usage lookup, at 200. `refresh_v2_dividend_batch.py` resumes through the catalog using the persisted `batch_sync.next_code`, preserves existing fields, and rechecks completed actual/forecast entries after 60 days; forecast lookup can require up to nine calls per issuer, so the R2 progress estimate is a lower bound and actual full-catalog completion against the recorded two-month target remains unconfirmed.

## Japanese market data

- The existing yfinance Ticker.calendar refresh may include Yahoo's next Dividend Date; sync_v2.py stores it as current.calendar.payment_start_date and records an independent status without making another request. The Worker exposes a matching date on upcoming_event and passes through an optional event-level payment_start_date. Android persists the optional date. In the annual dividend chart, Japanese ex-dividend months use the dividend event date; received months use payment_start_date when present and otherwise estimate record_date plus three months. US stocks and funds keep their existing event-month grouping.

- New listed-security market records are sourced from yfinance. Existing issuer/IRBANK financial and dividend records remain as provenance-bearing seed data; future yfinance records are added separately, and the store must not be reduced to yfinance-only records. J-Quants v2 supplies the eligible security-code universe; XTKS calendar sessions gate the scheduled run at 21:17 JST. Every active security requests one daily chart for the exact-session `Close` and one-year dividend/split candidates. Company names and current statistics from `Ticker.get_info()` refresh once per five published XTKS sessions using the same five-bucket rotation as annual financials; new securities fetch them before catalog inclusion, failed refreshes retain prior values and set `info_refresh_pending` for the next session, and cached statistics expose their last fetch session and a `stale` field status between refreshes. `sync.json` retains last attempt status and structured failure class/reason; the Worker exposes this metadata to Android, where Stock Detail shows the last successful company-information fetch date and a retry-pending failure state. Current statistics retain only app-used source inputs; deprecated fields are copied once to `archive/unused_statistics/{symbol}/statistics.json`. Yahoo-reported `trailingPE` and `priceToBook` are retained and preferred; calculations from the current close and positive trailing EPS/book value are used only when the corresponding reported value is unavailable, with value sources and input dates recorded. Yahoo `operatingMargins` is retained for analysis and converted from a fraction to percent; annual operating profit divided by sales remains the fallback. Current yield prefers Yahoo `dividendYield`, then IRBANK screening yield, then the available dividend and quote calculation. Historical yield minimum, average, and maximum keep their existing calculation. A missing same-session close fails the attempt and retains the previous published value. Normal event comparisons load the latest three calendar-year partitions; unchanged candidates leave historical partitions untouched. Initial migration, changed events, full-history rotation, or a newly detected split loads the full history as needed. Full action history and initial eight-year December-price records rotate across 20 persistent buckets; a newly detected split or reverse split refreshes full actions and all eight December closes for that security. Annual financials refresh on a new `lastFiscalYearEnd`/`mostRecentQuarter` marker checked during the five-bucket `get_info()` refresh, in the one-time five-bucket initialization, or after a 45-day safety interval; failed statement groups are retried independently. Same-session retries reuse successful company-information, close, event, and financial results. Yahoo missing-price errors and HTTP 404 are recorded as `no_data` and suppressed for the remainder of that market session; transient HTTP/network errors remain retryable within the four-attempt scheduled daily limit; manual sync intentionally permits five total attempts. Unknown exceptions are retained for diagnosis. December closes refresh after the last Tokyo session in December. Per-security R2 reads are cached for each worker task, and monthly-price migration inventories existing keys before reads/deletes. Publications record high-level yfinance method calls, phase timings, and R2 request timings; the collection phase also partitions wall-clock time into yfinance-only, R2-only, overlapping, and idle intervals. Catalog rows come from processed documents or the last published catalog; R2 profile/current/sync reads occur only for missing catalog rows. The first legacy migration took 134.46 minutes. A forced same-session post-migration reprocess on 2026-10-16 took 61.76 minutes, but it reused same-session results; a normal next-session full run is still required to establish recurring runtime and the monthly 2,000-minute budget.
- New objects use `market/yfinance/v2/`: current profile and quote, year-partitioned dividends and splits, up to eight December closing prices per security, and app-required annual financial inputs. Financial records use reporting-period-end keys (`YYYY-MM-DD`) so separate fiscal periods ending in one calendar year can coexist; existing `{year}.json` records remain readable and are updated when their exact period matches. The newest year-end price stays in the normal price area while older retained year-end prices use the per-security archive. Dividend charts and streak metrics use yfinance repaired event totals by calendar year and assume returned dividend amounts are already split-adjusted; neither the collector nor Worker reapplies split ratios. Streak metrics and their annual records are retained in each security's `current.json`; the daily XTKS sync initializes them from stored V2 event partitions and updates only completed calendar years. Within successfully fetched history, completed calendar years without observed dividend events are recorded as assumed zero for streak comparisons; years outside the covered history and failed fetches are not zero-filled. SciPy 1.18.1 and scikit-learn 1.9.1 are pinned for the repair path. Unused legacy yfinance fields are gzip archived for 10 years after v2 read-back.
- Annual V2 financial records retain yfinance's common-stock or total cash-dividend-paid row and exact `StockholdersEquity` separately from total equity including minority interests. When both cash dividends paid and positive period-end stockholders' equity are freshly available for the same annual record, the collector stores `calculated_doe = abs(cash_dividends_paid) / stockholders_equity * 100`, together with its numerator field, formula, and field status. Net D/E prefers yfinance's `NetDebt`; otherwise it subtracts same-period cash and cash equivalents or short-term investments from total debt, then divides by positive stockholders' equity (falling back to total equity including minority interests). Incomplete inputs and non-positive equity leave the ratio unavailable, and `field_status_reason` records missing input or fetch-failure reasons for each metric. The finance-data API passes these annual fields through from V2, and Android reads the latest annual `calculated_doe` and `net_de_ratio`. Policy version 2 schedules existing securities through five rotating groups; securities without prior per-security sync state initialize financials on their first normal universe sync. Normal collection then uses the fiscal-marker change trigger or 45-day safety interval. The server-side `refresh-all-financials` Actions mode refreshes and reads back all annual financial records for active V2 universe securities; it does not add a manual per-security control to Android. Android refreshes once per security for the financial payload contract so older device caches receive added fields.
- Each security's v2 `current.json` may include the next `Ex-Dividend Date` from `Ticker.calendar`, with source, retrieval status, attempt time, and successful fetch time. Calendar lookups refresh no more often than every 30 days to bound extra Yahoo requests. `/api/v1/dividend-months` prefers a recurring-date estimate from historical dividend events, then a future `Ticker.calendar` date, then the `Ticker.get_info` statistic. The rights-date artifact is regenerated weekly from up to ten years of stored events; it estimates a future event only when the same month appears in at least two distinct years in the latest five-year window, using the median day snapped to the nearest trading session. Android marks this source as historical inference. The XTKS calendar is used for `.T` symbols and XNYS for US symbols; the previous and next exchange sessions provide the calculated final-rights and estimated record dates. Historical estimates are excluded from rights-date notifications. Android requests dividend months for holdings and watchlist securities at startup and keeps the response in device preferences. Requests are gated by JST date and a 12-hour minimum interval; Stock Detail observes the cached portfolio data and can request a missing or newly selected security through the same gate. A failed request retains the existing cache.
- Android Stock Detail calculates a reference CAGR from the latest two to five consecutive calendar-year observed dividend totals when the starting amount is positive. The Worker returns V2 calendar-year consecutive-increase and no-cut counts with their calculation status; Android reads these explicit counts while retaining `未取得` when the source history is insufficient or failed.
- Android retains up to five verified observations per indicator from the same `/api/v1/financial-data/{code}` response and persisted JSON used for current metrics. The local financial-cache version is 7; the Worker unit contract remains 6. History preserves reporting dates, provider and basis, and validates and normalizes units before comparison. Consecutive comparisons stop at gaps, changed providers, or changed fiscal year-ends. Issuer records with only a fiscal-year label can describe year-to-year changes but cannot join exact-date financials; month-only dates join only one unambiguous reporting period. Current quotes and forecasts are not projected onto historical periods. The dividend-indicator explanation comments prioritize extreme-value interpretation, comparable annual changes, and same-period related indicators; missing history produces available-data commentary without a history-missing message. Numeric values, rating bands, and positions remain in row labels rather than being repeated in the body. These commentary branches do not change the existing rating scores or band/position codes.
- Stock Detail separates the four evaluation panels from the dividend-indicator explanation: panel headers retain values, bands, positions and score colors; panel bodies use indicator-specific 80–160-character explanations of relative position and boundary distance, without restating numeric band ranges or the header value. Nine interior positions, exact boundaries, just-crossed boundaries and open-ended distances select meaningful variants. A zero domain minimum is not treated as a transition to a nonexistent lower band. Percentage differences use percentage points. Open-ended bands show their single real boundary without inventing a terminal cutoff; unavailable comparisons do not fabricate positions or distances. The seven-metric scores and combination codes are unchanged.
- Dividend-indicator explanations choose finer extreme-value, boundary-nearness, deficit trajectory, dividend pause/cut/restart, and conflicting-indicator variants. The former detailed output for the same input sets the character ceiling; complete sentence alternatives replace existing slots instead of appending text or truncating sentences. All retained explanations include the indicator limitation. Same-period capital/FCF relations require aligned actual periods; current PER/operating-loss and long-growth/payout combinations explicitly distinguish acquisition timing and metric meaning. Missing or incompatible history produces available-fact explanations without history-missing notices. The four numeric evaluation panels, scores and combination codes are independent of these variants.
- V2 `current.json` retains Yahoo `payoutRatio` as a fraction and declares that source unit as `ratio`; public APIs convert it once to percentage points and declare `field_units.payout_ratio = percent`. The Worker uses the shared Yahoo statistics unit map only for older records missing per-field metadata; a present unsupported unit is rejected. API ratio conversion requires a declared `ratio` or `percent` unit. Android validates financial fields against their expected units, and `FinancialData.parse` normalizes declared payout units: percent points pass through while ratio/fraction values are multiplied by 100. For legacy payloads without unit metadata, annual dividend rows default to percent and the top-level Yahoo value defaults to ratio. The normalized result feeds Stock Detail and shared payout-risk evaluation.
- IRBANK annual actual DPS, disclosure-derived company forecasts, and screening `dividendYield` values are published to `market/yfinance/v2/issuer_dividends/current.json`. Current annual DPS in `/api/v1/live-quotes`, `/api/v1/security-search`, `/api/v1/search-catalog`, and `/api/v1/securities/{code}` prefers the IRBANK forecast, then its latest split-adjusted actual; current yield prefers IRBANK's screening value and falls back to the selected quote and IRBANK DPS only when that value is unavailable. These routes do not use Yahoo dividend amounts. `/api/v1/financial-data/{code}` builds issuer fiscal-year history from IRBANK v1 per-security dividend records and overlays the refreshed latest actual and forecast; it no longer uses Yahoo fiscal-DPS rows. The refresh script uses IRBANK `/dividends` for current actuals and parses current `DividendPerShare` facts from IRBANK disclosure documents. If a forecast spans an announced split and its adjusted interim amount agrees with the reported year-end amount, it uses IRBANK's actual-to-adjusted DPS factor to align the annual total to the latest share basis; otherwise it leaves the forecast unavailable rather than guessing. Calendar-year observed cash-distribution history and dividend-month events remain separate yfinance-derived series.
- The J-Quants master product category is retained so equities, ETFs, and REITs remain distinguishable; industry labels continue to come from the Android asset master. The collector sets Yahoo locale to `ja-JP`/`JP` and prefers Japanese `shortName`, Japanese `longName`, then an English name.
- The workflow in `.github/workflows/yfinance-r2.yml` starts at 21:17 JST on weekdays using the standard GitHub-hosted Ubuntu runner (free for this public repository). The XTKS gate selects a completed session; if a delayed run starts on a closed day, it reads the R2 schedule marker and catches up only when that session has not been published. The gate passes that exact session date to the collector, which refuses to publish a stale generation over a newer one. This closed-day recovery path requires the same read-capable R2 credentials as the sync and fails closed when R2 state cannot be read. Manual `check-calendar` dispatch exercises the gate and R2 read without starting a sync or writing to R2. The scheduled collector uses 24 ticker workers while limiting Yahoo request starts to eight per second. Deterministic sync tests run on relevant pushes and pull requests; manual dispatch supports tests, a non-publishing benchmark, calendar preflight, full R2 sync, full-universe yfinance company-information refresh, targeted and full-universe financial refresh, and one-time legacy data migrations. The `refresh-company-info` mode forces `Ticker.get_info()` for every active security and republishes the V2 records and catalog to R2. The full-universe financial mode reads the active security list from the published V2 universe and verifies each written annual record in R2. The benchmark measures the combined daily quote/action-candidate request and compares its unrepaired event values with repaired history, recording elapsed time, HTTP response count, decoded response bytes, event counts, and a fingerprint. The monthly rights-date workflow installs only `requirements-rights.txt` (`boto3` and `exchange_calendars`). The collector allows at most four per-security attempts per market day across reruns, with no in-run backoff sleep.
- Repository Worker search results read `catalog/current.json`, which contains price and calculated yield; detail requests read that symbol's `profile.json` and `current.json`. The API excludes symbols without a published profile and completed close. Dividend-month, monthly-price, financial-data, and `/api/v1/share-split-history` APIs read yfinance v2 objects only; financial and valuation responses do not fall back to IRBANK R2 or D1 rows. The one-time `migrate_legacy_financials.py` action copies only app-used annual fields into v2 with `legacy_migrated` field status and preserves seed values under `source_values.seed`; subsequent yfinance values are retained under `source_values.yfinance`, with yfinance preferred in the app-compatible flat field. Worker returns seed rows separately in `financials.seed_annual` and `valuation.seed_history`. Derived financial values record their input source categories. This preserves provenance without adding a legacy Worker fallback. The analysis API uses the latest v2 annual financial row and v2 market/dividend inputs; it does not fall back to D1 financial periods or security metric JSON. Dividend-month requests accept both a four-character code and a Yahoo `.T` symbol; split-history events are deduplicated by date and ratio, and stored events take precedence over a stale empty status. Before v2 event publication, dividend history reports `not_fetched` instead of treating IRBANK adjusted DPS as Yahoo event data. Calculated rights-date data is stored at `market/yfinance/v2/derived/rights_dates/current.json`. `/api/v1/live-quotes` serves completed catalog data only; it does not call Yahoo Finance. The hourly Worker trigger no longer enqueues Yahoo live-price collection, and any messages left in the retired quote queue are acknowledged without fetching prices. Production Worker read-back on 2026-10-17 returned generation `2026-10-16` with 4,341 catalog items; `security-search`, `live-quotes`, security detail, dividend-months, financial-data, split-history, monthly-price-history, and analysis routes responded for the sampled securities. The monthly-price API currently returns eight December closes for Toyota, but its stored date labels still need normalization to the final XTKS session.

## Review-fix contract additions (2026-10-20, local implementation)

- V2 catalog generations use `YYYY-MM-DD-<uuidhex>`; `market_data_date` and schedule session dates retain ISO date semantics. Worker accepts legacy date-only IDs and new IDs. Per-generation files are immutable; publication metadata and income-advice references share the ID.
- Financial refresh publishes `market/yfinance/v2/financial_revision.json`; Worker exposes its token at `/api/v1/financial-data/revision`. Android checks the token with a one-minute in-memory gate and bypasses a same-day per-security cache when the stored token differs. Financial, migrated dividend, IRBANK issuer-dividend, and IRBANK overview writers advance the token after writes. Scheduled analysis also compares that marker and the V2 catalog ETags. Consumers select financial/valuation periods by complete `period_end`, with guarded fallback for undated legacy rows.
- D1 migrations `0003_operational_schema.sql` and `0004_definition_defaults.sql` reconstruct operational tables and insert missing defaults without replacing operator definitions. ## Financial statement unit contract (2026-10-26)

- Yahoo Finance statement amounts use the explicit `yfinance_native` unit. The reported `financialCurrency` is retained as unverified provenance and does not establish the unit of those amounts. The Worker omits legacy Yahoo monetary fields without the native-unit marker; Android reads absolute financial amounts only when their unit is `jpy`. Equity ratio, operating margin, and FCF margin are accepted only from same-period, same-source inputs with matching units. Worker financial contract version 6 and Android payload contract version 6 trigger client refreshes after this contract change.


## Annual dividend source shared by assets and Stock Detail (2026-10-27)

`AnnualDividendResolver` selects current/future issuer fiscal-year forecast DPS, then the current JST year dividend-event estimate, then the unit-validated Yahoo forward annual dividend from `FinancialData`. Stock Detail's top card and runtime portfolio holdings call this same resolver. Forecast DPS determines annual dividends, evaluation/cost yields and confirmed-zero status, overriding cached trailing dividend/yield values. Quote and event refreshes reapply the forecast. Fund distributions retain their existing 10,000-unit basis and do not use stock forecasts. Asset refresh requests the same financial endpoint and current-year dividend events using the existing daily cache policies; no Worker data source is added.
